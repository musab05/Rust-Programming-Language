## 1. What Are Memory-Mapped Registers?

Hardware peripherals (GPIO, UART, SPI, timers) are controlled by reading/writing special memory addresses:

```
Memory Map (ARM Cortex-M)
──────────────────────────────────
0x0000_0000   Flash (code)
0x2000_0000   SRAM (data)
0x4000_0000   Peripherals ← registers live here
  0x4002_0000   GPIO Port A
    0x4002_0000   MODER (mode register)
    0x4002_0014   ODR (output data register)
  0x4002_0400   GPIO Port B
0xE000_0000   System (NVIC, SysTick)
```

Writing to `0x4002_0014` turns GPIO pins on/off — that's how you blink an LED!

## 2. Raw Register Access

```rust
#![no_std]
#![no_main]

use core::ptr;

// STM32F4 GPIO Port A registers
const GPIOA_MODER: *mut u32 = 0x4002_0000 as *mut u32;
const GPIOA_ODR: *mut u32 = 0x4002_0014 as *mut u32;
const RCC_AHB1ENR: *mut u32 = 0x4002_3830 as *mut u32;

unsafe fn blink_raw() {
    // Enable GPIOA clock
    let rcc = ptr::read_volatile(RCC_AHB1ENR);
    ptr::write_volatile(RCC_AHB1ENR, rcc | (1 << 0));

    // Set PA5 as output (MODER bits [11:10] = 01)
    let moder = ptr::read_volatile(GPIOA_MODER);
    let moder = (moder & !(0b11 << 10)) | (0b01 << 10);
    ptr::write_volatile(GPIOA_MODER, moder);

    // Toggle PA5
    loop {
        let odr = ptr::read_volatile(GPIOA_ODR);
        ptr::write_volatile(GPIOA_ODR, odr ^ (1 << 5));
        for _ in 0..100_000 { core::hint::spin_loop(); }
    }
}
```

**Problems:** error-prone, magic numbers, no type safety, easy to corrupt registers.

## 3. Volatile Access

Why `volatile` matters:

```rust
use core::ptr::{read_volatile, write_volatile};

// ❌ BAD — compiler may optimize away repeated reads
unsafe {
    let val = *(0x4002_0014 as *const u32);  // may be cached
}

// ✅ GOOD — volatile prevents optimization
unsafe {
    let val = read_volatile(0x4002_0014 as *const u32);  // always reads hardware
    write_volatile(0x4002_0014 as *mut u32, val | 1);    // always writes hardware
}
```

The compiler must not:
- Cache register reads (hardware can change values)
- Remove register writes (side effects matter)
- Reorder register accesses (order matters for hardware)

## 4. SVD Files

**SVD** (System View Description) is an XML file describing ALL registers for a chip:

```xml
<peripheral>
  <name>GPIOA</name>
  <baseAddress>0x40020000</baseAddress>
  <registers>
    <register>
      <name>MODER</name>
      <addressOffset>0x00</addressOffset>
      <fields>
        <field>
          <name>MODER5</name>
          <bitOffset>10</bitOffset>
          <bitWidth>2</bitWidth>
          <enumeratedValues>
            <enumeratedValue><name>Input</name><value>0</value></enumeratedValue>
            <enumeratedValue><name>Output</name><value>1</value></enumeratedValue>
            <enumeratedValue><name>Alternate</name><value>2</value></enumeratedValue>
            <enumeratedValue><name>Analog</name><value>3</value></enumeratedValue>
          </enumeratedValues>
        </field>
      </fields>
    </register>
  </registers>
</peripheral>
```

## 5. SVD2Rust

`svd2rust` generates a type-safe Rust crate from an SVD file:

```bash
cargo install svd2rust
cargo install form       # for formatting output

# Generate PAC from SVD
svd2rust -i STM32F411.svd --target cortex-m
form -i lib.rs -o src/
cargo fmt
```

This generates code like:

```rust
// Auto-generated by svd2rust — type-safe register access!
impl GPIOA {
    pub fn moder(&self) -> &MODER { &self.moder }
    pub fn odr(&self) -> &ODR { &self.odr }
}

impl MODER {
    pub fn write<F>(&self, f: F) where F: FnOnce(&mut W) -> &mut W {
        // volatile write with closure
    }
    pub fn modify<F>(&self, f: F) where F: FnOnce(&R, &mut W) -> &mut W {
        // read-modify-write
    }
}
```

## 6. Using a Generated PAC

```rust
#![no_std]
#![no_main]

use cortex_m_rt::entry;
use stm32f4xx_pac as pac;  // auto-generated PAC

#[entry]
fn main() -> ! {
    let dp = pac::Peripherals::take().unwrap();

    // Enable GPIOA clock
    dp.RCC.ahb1enr.modify(|_, w| w.gpioaen().enabled());

    // Set PA5 as output
    dp.GPIOA.moder.modify(|_, w| w.moder5().output());

    // Blink!
    loop {
        dp.GPIOA.odr.modify(|r, w| w.odr5().bit(!r.odr5().bit()));
        cortex_m::asm::delay(1_000_000);
    }
}
```

### Compare raw vs PAC:

```rust
// ❌ Raw: magic numbers, no safety
ptr::write_volatile(0x4002_0000 as *mut u32, (moder & !(0b11 << 10)) | (0b01 << 10));

// ✅ PAC: type-safe, readable, auto-complete
dp.GPIOA.moder.modify(|_, w| w.moder5().output());
```

## 7. From PAC to HAL

The HAL wraps the PAC with ergonomic APIs:

```rust
// PAC level (register-level)
dp.GPIOA.moder.modify(|_, w| w.moder5().output());
dp.GPIOA.odr.modify(|_, w| w.odr5().set_bit());

// HAL level (embedded-hal traits)
let gpioa = dp.GPIOA.split();  // split into individual pins
let mut led = gpioa.pa5.into_push_pull_output();
led.set_high().unwrap();  // uses OutputPin trait

// Driver level (portable)
let mut my_led = Led::new(led);  // works on any chip!
my_led.on().unwrap();
```

```
Your App
   │ uses
   ▼
Driver (portable)        ← embedded-hal traits
   │ uses
   ▼
HAL (chip-specific)      ← implements traits using PAC
   │ uses
   ▼
PAC (auto-generated)     ← type-safe register access
   │ generated from
   ▼
SVD (XML)                ← chip vendor provides this
   │ describes
   ▼
Hardware registers       ← actual silicon
```

## 8. Summary Cheat Sheet

```
MEMORY-MAPPED I/O
────────────────────────────────────────────────────────────
Peripherals controlled via special memory addresses
Must use volatile reads/writes
read_volatile() / write_volatile()

SVD → PAC
────────────────────────────────────────────────────────────
SVD file         XML describing all registers
svd2rust         generates type-safe Rust code
PAC              Peripheral Access Crate (auto-generated)

REGISTER OPERATIONS
────────────────────────────────────────────────────────────
.read()          read register value
.write(|w| ...)  write new value (replaces all bits)
.modify(|r, w| ...) read-modify-write (change specific bits)
.reset()         reset to default value

ECOSYSTEM LAYERS
────────────────────────────────────────────────────────────
SVD → PAC → HAL → Driver → Application
```
